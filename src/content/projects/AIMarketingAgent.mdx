The AI Marketing Agent helps employees turn their company's own documents into marketing strategy and copy. My collaborator started the platform in spring 2026, and I joined in August as the second engineer.

## How it works

A company's internal documents are split into chunks, embedded, and stored in a ChromaDB collection that belongs only to that company. Each document carries an access tier, so a sensitive executive deck never reaches someone without clearance.

When a user asks a question, a LangGraph supervisor decides which agent should act next. A researcher retrieves the documents that user is allowed to see, a strategist turns them into a plan, a copywriter drafts assets, and a brand reviewer sends weak copy back for another pass.

## What I work on

I design and direct the experiments that decide how the agent should be built, and define the evals that tell us whether a change helped.

- **Is the multi-agent supervisor worth it?** I led experiments comparing the LangGraph supervisor with a simpler single-loop agent, scoring both on outcome checks and token cost over a shared set of scenarios. The simpler agent held up well, so I proposed a plan to move to it, and we are now testing that more carefully before switching.
- **Can the agent remember what a team likes?** I defined a memory eval that checks whether the agent follows a team's preferences. Preferences learned from a reviewer's edits worked much better than ones the agent extracted on its own, which made improving automatic capture our next priority.

The lesson I keep relearning here is that a more elaborate agent design is a claim, and it needs an experiment behind it like any other claim.

## Stack

Python, LangGraph, OpenAI API, Pydantic, pytest.
