*In progress. ML engineering capstone, University of Toronto, Fall 2026.*

AI medical scribes listen to a doctor's appointment and write the clinical note. They save clinicians real time, and more clinics are adopting them every year. The catch is that the notes are not always right, and the companies selling scribes mostly grade their own accuracy.

ChartProof is our attempt at an independent check, a model that reads a visit transcript and its AI-written note and flags what the note got wrong.

## Why this problem

I authored our product landscape, surveying the commercial scribes, the frameworks health systems use to evaluate them, and the published research on where these notes go wrong.

Two things stood out. The most common failure is omission, something the visit covered that the note left out, and omissions are the hardest kind for a busy clinician to catch, because you cannot see what is missing. And the work on detecting these errors is largely done by the vendors themselves, which makes the seller the grader.

That second gap is the one we are building into.

## What I built

After the landscape work, my part moved to the data platform the rest of the pipeline stands on.

- **A data lake and warehouse.** I designed a medallion-style layout in S3, with raw, cleaned, and model-ready zones, and a PostgreSQL warehouse beside it. A Python loader checks each batch against its manifest, sets bad rows aside instead of failing the whole load, and writes through least-privilege database roles. My teammates built their stages on top of this design.
- **Infrastructure and CI.** I reworked the team's Terraform so both data pipelines run on ECS Fargate in separate dev and prod environments, and set up GitHub Actions to run migrations and the test suite on every pull request.
- **A disaster-recovery drill.** I planned and ran a recovery drill that rebuilt the production stack from Terraform and a database snapshot, to prove we could get working services back without losing data.
- **One shared generator library.** The benchmark and the live app each had their own way of generating data. I merged them into one Python library with local and cloud runners, so both routes score notes with the same judge.
- **The app's ingest worker.** I extended the app's SQS worker to move each job through the lake's zones, with dead-letter handling that marks failed jobs while keeping clinical text out of failure records.

## Stack

Python, PostgreSQL, AWS (S3, ECS Fargate, SQS, RDS), Terraform, GitHub Actions.
